# 分层剧本与模型生成

## 使用

目录侧边栏「故事转剧本」→选择 OpenRouter / OpenAI / 自定义兼容平台→输入基础地址、模型 ID 与 API Key→选择改编方式并粘贴原文→识别故事人物与大纲→逐一绑定预设演出形象并确认→建立事实账本与场景契约→逐场生成并检查→导入为新作品。

目录只显示作品→章节→场景。作品与章节可折叠并显示摘要；场景是点击后进入编辑的叶节点，不在目录展示台词。侧边栏的「作品操作」包含新建、故事转剧本、项目导入/导出、恢复备份与重置。场景沿用 ScriptDocument，台词与动作仍沿用原编译流程。旧项目在「未分章」中展示，不强制迁移。目录中的「编辑分层 / 摘要」可填写摘要或把当前场景移动到指定章；同名章节合并归组。「新场景」添加空白文档。

「案例故事」提供两部原创短篇《九点的影子》和《消失的十三秒》，每部均为两章四场，包含可编辑台词与演出动作，出演人物仅使用预设的成步堂、御剑、真宵、裁判长和矢张（证人）。新访客默认打开第一部；已有浏览器草稿仍优先加载。旧案例草稿的演员显示名会对齐预设，保留已编辑台词；重新打开案例可获得更新后的摘要文本。切换案例前会保存当前作品的本机备份，可在目录侧边栏恢复。

## 数据与生成边界

- ProjectManifest.narrative 保存作品摘要及有序章节；chapter.documentIds 引用已有场景。ScriptDocument.summary 保存场景摘要。兼容旧 0.7 项目文件，校验新字段与引用。
- 先从原文识别需要发言的人物和目录大纲。模型提供人物 ID 与姓名，但模型提供的形象映射会被丢弃；作者为每位人物选定预设形象并确认后，才建立事实账本和逐场契约。一个形象可以供多个故事人物使用，人物姓名仍沿用原故事。
- 账本区分已证事实、人物主张、推断、未知和新创事实；原文事实与人物主张必须带可定位的逐字片段。忠实改编禁止新创关键事实；允许扩写与原创续写可明确标记新增事实。程序校验引用、人物、场序和原文依据。
- 场景按顺序生成，每次包含本场契约、相关账本与原文片段、上一场出口和实际结尾。长于 12,000 字符的原文按引用提取片段。契约的入口、必要转折、出口与证据边界可编辑，不成为目录层级。
- 默认每场另发一次连续性检查请求。模型给出具体台词与依据的疑点，作者可重新检查或只重生成某场。疑点是警告，不会自动改写；硬校验失败会阻止该场保存。关闭自动检查可以减少请求，之后仍可检查未检查的场景。
- 模型只输出受限 JSON；程序赋予稳定 ID，映射现有背景与角色动作。未知角色、不可用动作、无效引用及截断结果阻止导入。
- 当前仅法庭 Adapter 与现有素材；保留故事人物姓名，形象可复用。初始背景是首条舞台指令，每句仍使用现有角色/姿态绑定机制。
- 当前生成动作范围：句首姿态、句末反应。导入后仍可在富文本编辑器添加其他现有动作。
- 故事输入最多 60,000 字符，大纲最多 12 章、总共 30 场，每场最多 80 句。当前请求按场串行，不是长篇小说分块系统。
- 已完成的场景保存在本机，失败后从下一场继续；修改大纲会使契约及场景失效，修改原文需要重做大纲；修改某场契约会清除该场及后续草稿。重建契约仅保留未受变化影响的前序场景，并将保留场景标记待重新检查。重生成某场后，后续场景保留台词、标记待检查。取消请求不会自动重试。
- 摘要是可编辑的创作数据，手工改台词后不会自动刷新，避免默默改写作者意图。
- 导入为新作品前保留当前作品一份本机备份，目录侧边栏「恢复导入前作品」可来回切换。它不是多版本档案，重要作品仍应导出。
- 每个场景分别保存尚未发送的输入草稿。切换场景保留已编辑文档，并重置该场景的撤销栈。

## 接入与隐私

调用 OpenAI-compatible Chat Completions，基础地址末尾由程序追加 /chat/completions。参考：
- https://openrouter.ai/docs/quickstart
- https://openrouter.ai/docs/guides/features/structured-outputs
- https://developers.openai.com/api/docs/guides/structured-outputs

当前为用户自带密钥的浏览器直连版本：API Key 不进入 localStorage、导出项目或源码，仅在页面输入框和请求期间的内存中存在。刷新或清除密钥可移除。故事、大纲、契约、相关台词及检查内容发送到用户指定的平台，按平台规则收费。自定义平台需要 HTTPS、兼容协议以及允许当前来源的 CORS。JSON 模式可关闭以适配不支持 response_format 的模型；输出仍须通过本地验证。尚未实现服务端代理、平台模型目录和费用预估。

## 验证

- 生成→角色/动作校验→编译→项目序列化/导入一致性。
- 无效人物、动作、重复人物 ID、非法章节引用被拒绝。
- 模拟 API 检查请求 URL、密钥不进入请求正文、HTTP 错误和截断错误。
- 两个案例的事实边界测试：停电记录与目击说法分开；录音时长差异与缺失片段的具体内容分开。无原文依据或错误事实引用被拒绝；语义疑点保留给作者判断。
- DOM 交互验证：启动、手动分层、切换场景的草稿隔离、第二场失败后重试不重复第一场、密钥不落本机存储、导入及备份恢复。
- 合并线上新版的排练素材预加载进度条。
- 未提供真实 API Key，因此没有执行真实付费调用。静态站点在当前环境无兼容的监督浏览器预览，未做手机浏览器视觉验收。模型的语义审阅本身不能保证识别全部矛盾；导入前仍需作者检查。
