# 分层剧本与模型生成

## 使用

2026-10-14：旧目录入口改为顶栏「作品管理」，在这里打开「故事转剧本」与 AI 设置。人物映射不会由模型决定：逐个人工选择内置人物，显示头像与姓名对应，全部确认后才建立契约；对白保留故事姓名。确认绑定到姓名和素材 ID，修改后需重确认，旧草稿的布尔确认标记不能跳过。新作品导入后可在作品管理中配置分支，见 [作品管理与分支剧本](BRANCHING_STORIES.md)。

目录侧边栏「AI 连接设置」→保存 OpenRouter Key 与模型偏好→「故事转剧本」→选择模型来源→选择改编方式并粘贴原文→识别故事人物与大纲→逐一绑定预设演出形象并确认→建立事实账本与场景契约→逐场生成并检查→导入为新作品。当前主入口有 **OpenRouter API** 与 **ChatGPT 账户额度**。OpenRouter 与角色生成共用连接，打开时刷新过期的文本模型目录，也可手动填写模型 ID；ChatGPT 账户模式不要求 OpenAI API Key，但当前静态站点没有账户桥。

目录只显示作品→章节→场景。作品与章节可折叠并显示摘要；场景是点击后进入编辑的叶节点，不在目录展示台词。侧边栏的「作品操作」包含新建、故事转剧本、项目导入/导出、恢复备份与重置。场景沿用 ScriptDocument，台词与动作仍沿用原编译流程。旧项目在「未分章」中展示，不强制迁移。目录中的「编辑分层 / 摘要」可填写摘要或把当前场景移动到指定章；同名章节合并归组。「新场景」添加空白文档。

「案例故事」现在只保留《告别逆转 · 最后的异议》：4章、8场、123段对白、10位发言角色。它是原创同人演示，不是原作逐字转录。素材库提供24位可绑定人物；案例不会强制加入全部人物。已有本机草稿优先加载。切换案例前保存当前作品的本机备份。

## 数据与生成边界

- ProjectManifest.narrative 保存作品摘要及有序章节；chapter.documentIds 引用已有场景。ScriptDocument.summary 保存场景摘要。兼容旧 0.7 项目文件，校验新字段与引用。
- 先从原文识别需要发言的人物和目录大纲。模型提供人物 ID 与姓名，但模型提供的形象映射会被丢弃；作者为每位人物选定预设形象并确认后，才建立事实账本和逐场契约。一个形象可以供多个故事人物使用，人物姓名仍沿用原故事。
- 账本区分已证事实、人物主张、推断、未知和新创事实；原文事实与人物主张必须带可定位的逐字片段。忠实改编禁止新创关键事实；允许扩写与原创续写可明确标记新增事实。程序校验引用、人物、场序和原文依据。
- 场景按顺序生成，每次包含本场契约、相关账本与原文片段、上一场出口和实际结尾。长于 12,000 字符的原文按引用提取片段。契约的入口、必要转折、出口与证据边界可编辑，不成为目录层级。
- 默认每场另发一次连续性检查请求。模型给出具体台词与依据的疑点，作者可重新检查或只重生成某场。疑点是警告，不会自动改写；硬校验失败会阻止该场保存。关闭自动检查可以减少请求，之后仍可检查未检查的场景。
- 模型只输出受限 JSON；程序赋予稳定 ID，映射现有背景与角色动作。未知角色、不可用动作、无效引用及截断结果阻止导入。
- 当前仅法庭 Adapter 与现有素材；保留故事人物姓名，形象可复用。初始背景是首条舞台指令，每句仍使用现有角色/姿态绑定机制。
- 当前生成动作范围：句首姿态、句末反应。导入后仍可在富文本编辑器添加其他现有动作。
- 故事输入最多 60,000 字符，大纲最多 12 章、总共 30 场，每场最多 80 句。当前请求按场串行，不是长篇小说分块系统。
- 已完成的场景保存在本机，失败后从下一场继续；修改大纲会使契约及场景失效，修改原文需要重做大纲；修改某场契约会清除该场及后续草稿。重建契约仅保留未受变化影响的前序场景，并将保留场景标记待重新检查。重生成某场后，后续场景保留台词、标记待检查。取消请求不会自动重试。
- 摘要是可编辑的创作数据，手工改台词后不会自动刷新，避免默默改写作者意图。
- 导入为新作品前保留当前作品一份本机备份，目录侧边栏「恢复导入前作品」可来回切换。它不是多版本档案，重要作品仍应导出。
- 每个场景分别保存尚未发送的输入草稿。切换场景保留已编辑文档，并重置该场景的撤销栈。

## 接入与隐私

OpenRouter 模式调用 OpenAI-compatible Chat Completions。参考：
- https://openrouter.ai/docs/quickstart
- https://openrouter.ai/docs/guides/features/structured-outputs
- https://developers.openai.com/api/docs/guides/structured-outputs

OpenRouter 模式为用户自带密钥的浏览器直连。勾选「记住在此浏览器」时，API Key 存在独立的浏览器连接配置中；取消勾选时仅在当前页面内存中使用。密钥不进入作品、故事草稿、导出文件或源码。「忘记此设备」移除已存连接，清除网站数据也会移除连接。这是浏览器存储，不是系统凭据库。故事、大纲、契约、相关台词及检查内容发送到 OpenRouter，并按 OpenRouter 规则计费。JSON 模式可关闭以适配不支持 `response_format` 的模型；输出仍须通过本地验证。

ChatGPT 账户额度模式是独立通道，不接受或保存 OpenAI API Key。2026-10-12 已按官方本地个人项目授权流程实现 OAuth 登录、身份校验、账号切换、Windows 加密保存、刷新及退出，前端调用同源 `/api/chatgpt/responses` 文本推理桥。符合条件的 Plus / Pro 账号可在官方页面授权使用订阅额度，账号模型列表由服务器读取；生成请求使用公开 Responses API，并等待完成事件。纯静态部署仍无此后端，图片生成暂不在官方订阅通道支持范围。真实用户授权后才能验证该账号的生成权限；详见 [ChatGPT 账号登录](CHATGPT_ACCOUNT_LOGIN.md)。

## 2026-09-29 接口与恢复检查
以下为历史检查记录，密钥保存行为已由 2026-10-12 的共用连接设置更新。
- 连接模型区域可执行一次简短JSON请求测试，明确由作者点击触发，不发送故事原文。
- 显示本次操作的等待秒数；每个请求最多180秒，可取消。
- 请求中锁定模型配置和密钥；取消后的迟到响应不进入草稿。
- HTTP错误、截断、无效JSON、空响应与取消均有本地回归覆盖；这不等同于真实平台调用验证。
- 当前执行环境没有用户API Key，没有发生真实模型付费调用。


## 2026-09-29 模型来源语义修正
- “OpenAI”不再等同于“OpenAI API Key”。产品目标改为：优先支持用户自己的 ChatGPT/OpenAI 账户额度，其次支持 OpenRouter API。
- UI 主入口缩减为 `OpenRouter API` 与 `ChatGPT 账户额度`。
- OpenRouter 继续是当前可直接工作的 BYOK 路径。
- ChatGPT 账户模式只访问同源账户推理桥，不携带 API Key；当前部署缺少该桥时给出显式错误，不做静默回退。
- 这项拆分是为了避免把 ChatGPT 订阅额度、OpenAI Platform API 余额和 OpenRouter 额度混为一谈。
