# 免费分享与展示前的最低准备

更新：2026-10-14。面向这套创作工具及其免费体验案例；以下是下一阶段的建议，不代表已经取得第三方素材授权。

## 1. 素材与代码的权利分别说明

当前已有源码、素材原图 / 生成记录和逐项喊话来源，但代码许可证还需要明确选择。代码许可不能覆盖 CAPCOM 的人物设计或原作录音。公开可下载、免费和署名本身不是录音再分发许可。

建议准备一个使用原创人物 / 可明确再分发声音的标准展示包；保留目前同人素材的来源与权利清单，再按适用的官方规则或授权条件决定分享范围。现有 17 段原作喊话尤其需要单独核对。CAPCOM 的[视频政策](https://www.capcomusa.com/video-policy/)明确说明视频规则本身不构成改作许可；这不能用作本工具素材包的授权证明。

官方[同人内容指南](https://www.capcom-games.com/ja-jp/fan-content-guidelines/)也需要阅读并确认适用范围；本轮访问被官网返回 403，因此没有据此宣称录音获准分发。最终公开展示应清楚写明非官方、与 CAPCOM 无隶属或背书关系，以及素材的作者、生成方式、来源和许可状态。

## 2. 一个完整、短而好懂的原创案例

目前六场 / 19 句的《雨停之前》已验证阅读与分支机制。面向新玩家，建议补成约 10–15 分钟的原创体验：开场引出问题，调查得到线索，询问暴露一处矛盾，玩家做出选择，抵达明确结局。重点是对白与推理成立，分支数量可以少。

制作「阅读版 HTML」和「可编辑 .yahari」各一份；附操作说明、素材来源、预计时长、已知限制。让第一次看到的人无需注册、无需 AI Key，也能读完。

## 3. 一次外部验收与基本交付

本地已有 188 项测试，桌面 / 375px 浏览器 / 离线 HTML 验收。分享前仍应找 5–10 位未参与开发的人，在真实手机和电脑上完成开始阅读、选择、退出继续、静音、导入 / 保存；收集卡住的步骤和丢稿问题。至少补测 iOS Safari、触屏 / 软键盘，以及更大作品。

固定一个发布版本与更新记录，提供反馈 / issue 入口、浏览器保存和备份说明。说明哪些功能可离线使用，哪些需要外部 AI 服务；ChatGPT 账户生成目前需要本机桥接服务，静态站点不提供该桥接。不同站点的浏览器草稿不会自动同步，应通过作品包迁移。

## 4. 给卡普空的展示材料与合适渠道

准备一页中 / 日 / 英介绍和 60–90 秒录屏，展示作品管理、动作绑定、保存与离线阅读，写清工具解决的创作问题、当前实现和希望讨论的事项。代码许可、案例素材许可和第三方依赖分开列出。

联系前应确认对方愿意接收相关技术展示；不要默认普通客服入口会受理游戏提案。日本官方[PC 意见表单](https://www.capcom.co.jp/support/form_pc2/)写明不受理游戏企划 / 创意，美方[网站条款](https://www.capcomusa.com/terms/)也说明未征集建议的接收政策与反馈条款。具体渠道应按实际地区、身份和联系目的确认。未经邀请，不发送需要保密的详细企划或希望对方承担保密义务的材料。

推荐下一步：先确定分享版素材与代码许可，再完成短案例，然后进行陌生用户验收。完成这三项，就能拿到比继续增加功能更有说服力的演示与反馈。
