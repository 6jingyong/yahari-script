## 现状与判断

- Core 已用 `ResourceRef { packId, id }` 引用素材，项目清单也声明所需内容包；这两个边界可以保留。
- `content-packs/courtroom-demo/catalog.json` 把人物、背景、音频及资源都放在一个包中，构建脚本 `scripts/generate-content-packs.mjs` 只处理这个固定路径。新增第二个包目前仍需改构建代码。
- `CourtroomContentPack` 强制要求 `stageScene` 和人物的法庭站位，适合法庭演出，却不足以表达一般舞台。主题包若只换图片，也会继承法庭布局。
- 原创人物已支持手动图片和 OpenRouter 图片请求，现已迁移为独立素材工作区，支持设定、多动作及素材包导入导出。本轮图片已迁移到 IndexedDB Blob；兼容 JSON 仍内嵌 data URL，新 `.yahari` 包存二进制图片。0.8 项目边界仍限制最多 4 个嵌入包、每包 100 张图片、图片 data URL 合计 20,000,000 字符；扩大主题包规模还需要调整格式上限。
- 故事生成和人物图片分别在 `packages/story-ai/src/model.ts` 与 `apps/editor/src/original-character.ts` 实现请求；2026-10-12 已复用 `apps/editor/src/ai-connection.ts` 的连接配置和 `packages/ai-providers/` 的模型目录。请求传输尚未完全归并到提供商层。

结论：需要调整数据与工作流边界，但不需要立即重排现有素材文件。先让包可独立安装、人物可编辑、连接可复用，再渐进迁移图片存储。

## 三层内容模型

1. **演出适配器**定义动作语义、校验、编译和布局能力。例如当前法庭演出；未来普通对话舞台可提供中性适配器。不同画风或作品来源本身不需要新适配器。
2. **主题包**提供人物、背景、音效、音乐、视觉主题及可选场景模板。一个项目可引用多个兼容包，引用采用稳定的 `packId + resourceId`，并锁定包版本。
3. **作品素材**保存用户原创人物及对现有角色的增补，随作品导出。现已增加跨作品复用的独立素材库，但项目导出必须包含实际使用的原创资源，避免换设备后丢图。

“逆转裁判包 / 弹丸论破包 / 柯南包”应首先是主题包：若只是人物、场景和风格，它们可共用中性小剧场能力；只有特殊演出规则或玩法确实不同，才增设适配器。发布第三方 IP 包前需确认素材来源和使用许可，包元数据应记录来源与许可。

## 推荐目录与资源契约

```text
content-packs/
  courtroom-demo/
    pack.json                 # 包 ID、版本、兼容适配器、依赖、来源
    characters/
      phoenix/character.json  # 人物资料、动作 ID、资源引用
      phoenix/assets/         # 只放这个人物的运行素材
    scenes/                   # 背景、前景、场景布局
    audio/
    themes/                   # 界面/字幕/转场风格，可选
    shared/                   # 跨人物图集等共享资源
    source/                   # 源图和工程文件，不进入运行包
  another-pack/
    ...
packages/
  ai-providers/               # 连接配置、模型目录、文本/图片请求适配
```

这是目标结构，不要求一次性移动现有资源。第一步让生成脚本发现各包的清单，保留旧 `catalog.json` 作为兼容输入。人物动作仍引用资源 ID；共享图集留在 `shared/`，不为迎合目录而复制图片。

内置人物应视为只读。用户添加动作时生成作品级扩展：记录被扩展人物的包 ID、人物 ID、新动作 ID 和图片资源，解析能力时叠加显示；冲突 ID 必须拒绝或明确重命名。旧剧本中的原动作引用继续有效。AI 生成结果先进入预览和编辑，再由用户确认写入扩展。

## 界面

在写作区之外增加独立的“素材库”入口：人物、场景、音频、主题包。人物详情展示设定、立绘、动作和表情，并提供“添加动作”“建立原创角色”“AI 生成”三个明确入口。角色卡标注来源：内置包、已安装主题包、此作品原创；对内置人物的增补显示为“此作品扩展”。

“AI 连接”放在设置中，由故事生成和素材生成共用。生成弹窗只展示当前连接、任务适合的模型列表和费用提示，不再重复输入 Key。打开生成弹窗时刷新过期的模型目录；按文本/图片能力筛选，允许搜索、手动填模型 ID、手动刷新。目录获取失败时保留上次结果，并提示可能过期；不能静默改用另一个模型。模型是否支持 JSON、图片输出等能力应在选择与请求校验时检查。

## 本地保存连接

- 保存提供商、模型偏好和密钥的范围是“当前设备/浏览器”，不写入作品、导出文件、源码、日志或分享链接。
- 提供“记住此设备”“测试连接”“更换 Key”“忘记此设备”及可见的当前连接状态。首次保存时说明浏览器网站数据清除后连接会消失。
- 静态网页可用浏览器持久存储实现免重复输入，但它无法提供 VS Code 那样的系统凭据保护；同源脚本可读取保存在浏览器中的密钥。若要系统凭据保护，应由本地启动器增加受限的本机凭据桥，网页只保存连接标识。两种存储后端使用同一个设置界面。
- 模型目录与密钥校验分开：能取得公开目录不代表 Key 有效。列表字段、模型能力及图片接口须在接入时对照 OpenRouter 当时的官方文档核实。

## 迁移顺序

1. **先完成一个原创小剧场闭环**：两名原创人物、一张自有背景、排练、导出和另一浏览器导入。这会暴露真实的布局和包需求。
2. **建立素材库与包清单**：让第二个简单原创主题包不改编辑器代码即可加入；提供角色详情与作品级动作扩展。保留旧包 ID 和资源 ID，不破坏现有剧本。
3. **迁移本地素材存储**：项目元数据与图片 Blob 放 IndexedDB；导出为包含清单和素材的可移植归档，导入时验证路径、大小和类型。旧 `0.7/0.8` JSON 项目继续可读。浏览器存储升级前保留原始数据直到校验成功。
4. **统一 AI 连接**：故事和图片复用提供商层，加入持久连接、动态模型列表、能力过滤和费用提示。用模拟接口验证模型列表变化、错误与离线情况，再用用户自己的连接做一次真实验收。
5. **增加中性演出适配器**：由原创场景的实际需求确定舞台槽位、镜头和转场；最后再制作更多主题包。

优先级：素材库与可移植存储高于大规模整理图片目录；统一 AI 连接可与素材库并行设计，但不应把 API Key 混进内容包或作品格式。

模型目录已按官方接口分开：文本使用 `/api/v1/models?output_modalities=text`，图片使用 `/api/v1/images/models`。图片请求保留 `/api/v1/images`；参见 [OpenRouter 图片生成指南](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)。真实验收目前只覆盖一次免费文本请求，图片接口仍以模拟检查为证。
