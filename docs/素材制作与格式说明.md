# 素材制作、尺寸与默认压缩

更新：2026-10-13。适用于当前本地版；页面顶栏 **素材管理** → **格式、尺寸与压缩说明** 也可查看处理规则。

## 现有素材怎样管理

内置的 **24 个角色、192 个动作、23 个场景、35 个 8Bit 音效和 16 段循环配乐** 已统一进入素材管理。图像来源可筛选「内置及其调整」或「原创 / 导入」，声音按类型与用途筛选。动作在角色编辑中管理；舞台背景、透明前景在角色或场景的「舞台图层」中管理。

- **修改 / 增补**：可以改名称、设定、标签、立绘与场景图，增加或移除动作、替换动作图片、调整动作类别和舞台图层。至少保留一个姿态。内置角色和已有动作的 ID 保留。
- **保存到素材库**：保存本机原件。明确点击「用于当前作品」或「将保存版本用于当前作品」才更新作品；Ctrl+S 保存当前素材或包资料。正在被作品使用的动作不能删除或改类后覆盖作品，先修订剧本中的引用。
- **移除内置素材**：从本机列表隐藏，已有作品继续保留；「恢复已移除内置素材」会恢复列表，并保留此前保存的调整。隐藏的角色不再作为新增人物预设；隐藏的场景不再作为新背景选项，已使用的背景仍可显示。
- **恢复默认**：清除该内置素材的本机调整，再显示原始版本。已有作品保留其版本，重新用于作品才更新。
- **删除原创 / 导入素材**：删除素材库原件，已加入作品的副本保留。

本机原件属于当前浏览器及站点地址；换浏览器、端口或设备请导出迁移。内置目录无需预先复制全部图集；编辑、使用或导出时才裁切所需图片。旧素材库自动升级并保留已有包和图片。

## 图片格式与制作尺寸

| 用途 | 支持格式 | 推荐尺寸与制作方式 |
| --- | --- | --- |
| 角色立绘 | PNG、WebP；JPEG 也可上传 | 建议透明底、半身构图，512×384 或 768×576；人物居中，完整保留头发，腰线基线一致 |
| 单个动作 / 表情 | 同上 | 同一角色保持画布尺寸、人物比例与位置一致；每个动作上传一张独立图片 |
| 场景背景 | PNG、JPEG、WebP | 推荐 768×576，4:3；通常使用不透明图 |
| 舞台前景 | PNG、WebP 推荐；JPEG 可上传但没有透明底 | 推荐 768×576 透明画布；只画遮挡角色的桌面、栏杆等前景 |

这些是推荐尺寸，不是强制裁切规格。竖图、方图也可以上传，处理时保留比例，不会拉伸或强制裁成 4:3。JPEG 不支持透明底，角色和前景优先使用 PNG / WebP。

当前内置 **24 名角色全部使用半身构图**：立绘和动作单格为 **512×384**，4×2 动作页为 **2048×768**，腰线位于单格 `y=372`，四周留透明边距。同一角色的八个动作使用共同缩放比例；头像取同一动作页的常态格，避免头像与动作形象不同。内置场景与舞台图层为 768×576。编辑器按真实裁切框导出单张动作，保留透明通道，不会导出整个动作图集充当一个动作。

角色默认名称统一采用早期民间译名与完整人名；「绫里春美」「叶樱院绫美」等旧简称或其他译法仍可搜索。已有作品的自定义人物昵称、本机素材调整及已导出的包保持作者版本。修订记录、完整译名表和生成提示词见 [内置人物素材修订](内置人物素材修订.md)。

手动上传不自动识别未知图集，请先自行拆分成单张动作。SVG、GIF、视频及骨骼动画暂不作为图片素材导入。立绘 / 场景预览下方显示实际尺寸、格式和约略文件大小；动作图片悬停可查看尺寸。

## 默认压缩流程

手动上传、AI 图片以及从内置图集提取的可编辑图片使用同一规则：

1. 手动文件最大 **10,000,000 字节（10 MB）**；图片宽、高分别须在 **1–8192 像素** 内。
2. 等比缩放至 **最长边最多 768 像素**；小图不放大。例如 1600×1200 → 768×576，480×640 → 保持 480×640。
3. 浏览器编码为 **WebP，质量参数 `0.76`**，保留透明底。质量参数不是「压缩至原文件的 76%」，最终大小取决于画面复杂度和浏览器编码器。
4. 若编码后的 data URL 超过 **900,000 字符**，宽高再缩至当前的 **80%**，以 WebP 质量参数 **`0.65`** 重编码一次；仍超限则提示失败，保留已有素材。这个上限约相当于 675 KB 图片字节，不能把它理解为 900 KB 文件。
5. 浏览器没有 WebP 编码能力时使用其 PNG 回退结果，同样执行大小限制。

压缩是有损处理，建议自己保留原始高清文件。再次上传会重新编码；从已有素材库导出、导入包则不再次压缩图片。素材库按 SHA-256 内容哈希存储 Blob，同一图片字节去重；ZIP STORE 包直接存图片字节，不再增加 ZIP 压缩。

**内置发行文件的构建规则单独保留**：源 PNG 在 `content-packs/courtroom-demo/art-source/`，运行图由构建脚本转为 WebP，Pillow 参数 `quality=88, method=6`，保持尺寸与透明通道。页面的本机调整不会改写这些源文件；裁切成可编辑素材后遵循上面的浏览器压缩规则。维护发行图的方法见 [美术方向与构建步骤](../content-packs/courtroom-demo/ART_DIRECTION.md)。

## 素材包与作品文件

| 文件 | 保存内容 |
| --- | --- |
| `.yahari-characters` | 角色设定、立绘、动作、可选舞台背景 / 前景、来源与许可 |
| `.yahari-scenes` | 场景说明、背景、可选前景、来源与许可 |
| 上述后缀加 `.json` | 相同数据，图片以 data URL 内嵌 |
| `.yahari-sounds.json` | 程序合成声音的音符、波形、音量、时间参数和隐藏状态 |
| `.yahari` | 作品正文、人物绑定、自有图片及已应用的内置调整、声音设置 |

内置导出的角色 / 场景包包含裁切后的完整图片及原来源标记；不会携带整张动作图集或 AI 凭据。用于作品时，内置调整集中在一个作品包中，保留原角色 / 动作 / 场景引用，只嵌入改动图片和新增动作。作品文件仍声明并依赖相应版本的内置主题包；独立角色 / 场景包可以携带该素材的全部图片。

独立角色 / 场景包最多 50 个角色或场景、每角色 50 个动作、99 张图片，图片 data URL 合计最多 20,000,000 字符，包文件最大 32 MB。当前作品最多 4 个自有包、每包 100 张图片；内置调整合计占用其中一个包。导入校验格式、引用、大小、条目路径与 CRC，通过预览确认后才保存。

内置来源和许可随包保留；修改或导出内置素材不改变其角色权利。当前示例的生成同人插画及 CAPCOM 角色说明见 [第三方素材说明](../THIRD_PARTY_ASSETS.md)。原创角色可以保存自己的来源和许可。

## 声音素材

现有声音包括 **35 个原创 8Bit 音效与 16 段原创循环配乐**。声音页按演出用途分类，设置常驻；可修改名称、分类、使用说明、方波 / 三角波 / 噪声音色、相对音量与速度。每个音符可以保留独立声部，配乐包含旋律、低音与噪声节拍。旧正弦 / 锯齿波参数兼容读取。新声音默认是短提示音。

素材试听与播放器共用 12kHz 单声道、8Bit 阶梯合成。「下载 WAV」导出当前设置的 8-bit PCM 文件；JSON 参数包保留可编辑的音符、分类和说明。当前不支持上传音频文件。试听播放一遍，配乐在演出中循环；声音开关由用户控制。相对音量与速度以当前保存版本为基准，多次调整会累积。

点击「应用到当前作品」后，该版本进入作品文件。移除或覆盖本机声音列表不自动更新作品；应用时会阻止移除剧本仍在使用的声音。声音包导入会确认替换本机列表，已有作品保留原版本。声音包最大 500,000 字节，最多 80 个预设、每个最多 32 个音符；参数需通过范围检查。类型、原始资源 ID 与分类信息兼容已有作品。完整说明见 [8Bit 声音](8BIT_AUDIO.md)。

完整主题包（音频文件、布局、依赖与大量素材）的安装系统仍待后续实现；当前角色包、场景包和声音参数包可分别使用。
